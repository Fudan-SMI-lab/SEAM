# 共建Git仓库

SEAM 是一个持续迭代的开源项目。

您可以通过反馈问题、提交功能建议、补充文档、贡献适配经验或提交代码的方式参与共建。无论是修复一个错别字、补充一个迁移案例，还是新增一个平台适配能力，都是对 SEAM 社区有价值的贡献。

多种贡献请查阅[SEAM文档库](https://alidocs.dingtalk.com/i/nodes/9E05BDRVQ2b37ePOFPaEll9kJ63zgkYA)，本文档仅介绍Git仓库代码贡献方式。

---


## Git仓库参与方式

你可以通过以下多种形式为本项目贡献力量：

1.  **代码贡献**：提交代码实现功能迭代与问题修复
    
2.  **反馈问题**：协助我们发现并修复代码缺陷
    
3.  **功能提议**：提交新功能构想与优化建议
    
4.  **项目推广**：向身边开发者分享、推荐本项目
    

## 代码贡献操作方式

1.  在 GitHub 上 fork 这个仓库。
    
2.  在你的 fork 仓库中进行更改。
    
3.  提交一个 PR。
    

**具体地，请遵循以下流程：**

1.  Fork 当前仓库至个人账号
    
2.  基于 `main` 分支新建自定义分支（示例分支名：feature/xxx、fix/xxx）
    
3.  完成代码修改，严格遵循项目编码规范
    
4.  本地充分测试，确保改动可正常运行
    
5.  编写规范的提交说明，清晰描述变更内容
    
6.  将代码推送到你个人的 Fork 仓库
    
7.  向本仓库 `main` 分支发起 Pull Request
    

我们会及时审核 PR，与你沟通细节，共同完成代码合并。

## 反馈问题

若你在使用过程中发现 Bug 或异常问题，请按如下流程提交：

1.  前往 [Issues](https://github.com/Fudan-SMI-lab/SEAM/issues) 检索，确认该问题是否已有人提交
    
2.  若无相关记录，点击「New Issue」，填写清晰的标题与完整问题描述
    
3.  补充运行环境、复现步骤等关键信息，方便我们定位排查。Issue描述尽量详尽，比如：问题标题、运行环境、目标 GPU 平台、原始项目介绍、复现步骤、报错信息、SEAM迁移报告、日志等
    

## 功能提议

如果您希望 SEAM 支持新的 GPU 平台、新框架、新模型类型或新的报告能力，或者有不错的新功能或优化想法，可以提交 Feature Request。

1.  先在 [Issues](https://github.com/Fudan-SMI-lab/SEAM/issues) 查看，避免重复提议；
    
2.  确认无重复后，新建 Issue 并选择「Feature Request」模板详细描述方案。
    

建议说明包含：需求背景、用户场景描述、当前痛点、期望功能、是否有可测试项目或样例。

如果您觉得Git仓库提交 Feature Request复杂，也可以在通过联系我们中的邮件或者钉钉群反馈给我们。
