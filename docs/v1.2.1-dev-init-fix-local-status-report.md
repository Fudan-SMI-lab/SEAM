## 3. 重点问题与证据

### 3.1 已完成静态实现、等待端侧验收

#### 序号 1：复现环境或复现步骤

`write_usage_guide()` 不再只写未经验证的 `.venv` 假设，而是根据实际解释器、环境类型、namespace、容器或命令事实生成复现说明。验收时应在干净环境中仅依赖 `migration_reports/USAGE.md` 完成一次推理。

#### 序号 12：空目录快速失败

`src/harness/project_preflight.py` 已在启动 OpenCode、创建会话和进入 LLM 阶段之前校验项目目录，区分不存在、不是目录、为空、仅含忽略项和正常项目。端侧需确认失败时没有遗留服务、会话和输出副本。

#### 序号 13、14、17：产物路径与报告发布

三项共享同一根因：内部运行证据目录、迁移项目目录和用户报告目录此前混用。当前实现已：

1. 使用真实 `Path`/summary 数据输出路径；
2. 分别展示 `Migrated project dir`、`Migration reports dir` 和 `SEAM run report dir`；
3. 将 Phase 6 报告受控发布到 `<migrated_project>/migration_reports/`；
4. 要求 `SUMMARY_REPORT.md` 存在后才能完成发布；
5. 只在文件真实存在时把它写入 `USAGE.md`。

端侧验收必须逐个 `test -e` 日志中打印的路径，并从 `USAGE.md` 直接打开 `SUMMARY_REPORT.md`。

#### 序号 15：OpenCode 生命周期

当前实现区分“运行前已存在的服务”和“本次 SEAM 自动启动的服务”。只清理由本次运行持有的进程，并补充了中断清理。端侧需覆盖正常完成、失败、`Ctrl-C`、预先已有服务四条路径。

#### 序号 16：日志时区

统一时间工具输出带 `Z` 的 UTC ISO-8601 时间，并为 Python logging 配置 UTC formatter。端侧还需检查 TUI、`core.*`、workflow 文本和 `ui_events.jsonl` 是否均采用一致且可解析的时间语义。

### 3.2 本轮新合入能力

- Phase 5 上下文管理：上下文达到阈值后进行快照、压缩或轮换，并限制恢复/重发次数，避免无限循环。该能力与钉钉序号 10 的症状相关，但不能替代 PPU 实机验收。
- 运行时产物文件名限制：避免长项目名在 NPU/Linux 文件系统触发 `Errno 36`；短文件名保持原样，长文件名按 UTF-8 安全截断并追加稳定哈希。
- 运行时间线：执行器持久化运行和阶段开始/结束时间，Phase 6 报告只消费权威时间事实，避免由模型生成 `—` 占位。

- 序号 7、8：PPU + vLLM/SGLang；
