贡献原则

贡献适配经验时，重点是让别人能够判断、复现和复用。建议遵循以下原则：

  • 说明清楚原始项目、目标 GPU 平台和运行环境
  • 提供真实运行结果，不只描述代码修改
  • 保留关键命令、日志路径和报告路径
  • 明确哪些问题已经解决，哪些问题仍未解决
  • 删除密钥、内网地址、私有数据集路径等敏感信息
  • 只提交自己理解的内容；如果某个修复来自他人建议，需要说明来源或背景

什么是适配经验

某个项目从 CUDA 迁移到国产 GPU 过程中形成的可复用信息，包括：

已完成迁移的模型案例 不同 GPU 平台的适配经验 依赖安装与环境配置说明 某类错误的解决方法 框架在目标 GPU 上的特殊配置 自定义算子的迁移方法 性能与精度验证报告 可复现的测试脚本 平台专用工作流与 prompt 模板 避免 CPU fallback 的检查方法

一份适配经验应包含什么

内容说明
项目名称被迁移的模型或代码项目
原始环境原本运行的 CUDA、PyTorch、Python 等版本
目标平台阿里 PPU、昇腾 NPU、沐曦 GPU 或其他平台
使用框架PyTorch、vLLM、SGLang 等
问题现象报错信息或异常表现
解决方法实际采用的修改方式
验证结果是否端到端通过，是否有性能或精度报告
注意事项后续用户复用时需要注意的点
推荐写法：在昇腾 NPU 环境中，项目启动时报 xxx 错误。原因是依赖版本与 CANN 工具链不匹配。 将 xxx 版本调整为 xxx 后，入口脚本通过端到端验证，报告路径为 xxx。
不推荐写法：改了一些依赖后可以跑了。
Way 03

.memory 文件分享

SEAM 每次迁移完成后，会评估成功与失败的案例，把有效的适配方案提炼为可复用技能（skill）， 存入 .memory/skills/ 和 .memory/memory/ 目录，为下一次运行提供参考。

这些积累就是 SEAM「越用越聪明」的底层机制：零先验运行、 跨案例知识迁移、边际成本趋近于零。 分享你运行过程中产生的 .memory 内容，等于把一次适配的经验直接交给下一个人。

.memory、.skill 等文件夹会在运行中自动更新，是 SEAM 的自进化学习经验记忆和技能素材， 非必要勿删。分享前请先剔除密钥、内网地址、私有数据集路径等敏感信息。
SEAM 运行后产生的经验目录 
SEAM/
├── .memory/
│   ├── skills/      # 可复用技能（skill）
│   └── memory/      # 案例记忆（memory）
├── .skill/          # 运行时更新的技能素材
└── e2e-reports/
    └── src/<时间戳>/
        └── summary.json   # 更完整的运行结论

# 迁移后项目侧
output_projects/<项目名>_<时间戳>/
├── migration_reports/   # 验收结果 / 性能 / custom-op / 构建日志
└── .sm-artifacts/       # 详细运行时 log
Way 04

资源共享：两大难题等你贡献

从 SEAM 侧理解，当前还有两大资源难题，直接决定了国产 GPU 能不能被更多人「用起来」。

缺国产 GPU 试用环境

用户在决定用国产 GPU 之前，首先最缺乏的是：缺少国产 GPU 环境去「试一把」的机会。 因此，如果有可贡献给 SEAM 用户免费使用或者优惠使用的国产 GPU 环境，我们会非常欢迎并协助做推广。

缺 AI tokens

SEAM 使用过程中需要配置 AI 大模型的 API key（也就是要花费 tokens），但很多不同领域的用户， 对于 tokens 的购买很不熟悉，阻碍了使用能大幅度减轻适配工作量和时长的 SEAM， 在冗长的自己手动去做迁移适配的工作里对国产 GPU 失去信心。 因此，我们也非常欢迎能免费贡献的 API tokens 供 SEAM 用户使用。
