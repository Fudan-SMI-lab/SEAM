开始你的第一次迁移

SEAM 是 MIT 协议开源的自动化迁移工具。请在你真正要运行迁移结果的那台国产 GPU 环境中启动它 —— 这样 SEAM 才能基于真实硬件反馈完成检测、运行、修复与验证。

Install

运行前准备与安装

SEAM 需要在目标国产 GPU 服务器或对应容器环境中运行。

运行前请确认已准备好

  • 原始 CUDA 项目代码
  • 一台可访问目标国产 GPU 的服务器或容器
  • Python 运行环境（生产支持契约：Linux + Python 3.10+）
  • 目标 GPU 平台对应的软件栈、驱动和 SDK
  • OpenCode Server 或 SEAM 当前支持的代码智能体运行服务
强烈建议在「真正要运行迁移结果的国产 GPU 环境」中启动 SEAM。 切换到别的环境运行，SEAM 拿不到真实硬件反馈，迁移结论也就无从验证。

为什么需要 OpenCode

SEAM 运行时需要依赖 AI 模型 API 等服务。SEAM V1.0 使用的是 opencode —— 一个支持同时使用多个不同模型的开源 coding CLI，更适合在国产显卡的终端使用场景。

安装 OpenCode 
curl -fsSL https://opencode.ai/install | bash

# 启动 OpenCode Server（默认 127.0.0.1:4098）
opencode serve --hostname 127.0.0.1 --port 4098

# 检查服务是否在运行
curl -s http://127.0.0.1:4098/global/health
安装命令 — 下载 SEAM 并准备环境 
# 获取 SEAM
git clone https://github.com/Fudan-SMI-lab/SEAM.git
cd SEAM

# 创建虚拟环境
python3.10 -m venv .venv
source .venv/bin/activate

# 安装 SEAM 依赖（含 dev 测试工具链与 dashboard 渲染器）
pip install -e "src/[dev,dashboard]"
基础运行命令 
# 在 SEAM 根目录执行
bash src/scripts/run_seam.sh /path/to/your_original_cuda_project

# 端口不同时显式指定 server；并指定输出目录
bash src/scripts/run_seam.sh /path/to/your_original_cuda_project \
  --server_type opencode \
  --server_url http://127.0.0.1:4098 \
  --output-dir /path/to/output_root

不传 --workflow 时，启动器会使用 src/workflows/seam_auto_default.yaml 自动选择流程，通常无需手动指定。 项目根目录下的 ADAPTATION_REQUIREMENTS.md 会自动加载。

Quick Start

五步完成第一次迁移

快速完成您的第一次 SEAM 迁移。

1

进入国产 GPU 环境，准备原始待迁移的项目仓库

在目标国产 GPU 服务器或容器中，例如阿里 PPU、昇腾 NPU 或沐曦 GPU。准备一个原本可以在 NVIDIA CUDA 环境运行的 AI 项目仓库，可以是 PyTorch、vLLM、SGLang 或其他待适配框架项目。建议首次测试选择规模较小、入口清晰的项目，方便快速验证环境和迁移流程。

2

启动 OpenCode Server

确认本机 OpenCode Server 已启动，默认地址为 http://127.0.0.1:4098。如果端口不同，后续运行命令中需要通过 --server_url 指定。也可以由 SEAM 自动启动，前提是已经安装了 opencode 且需要用的 Token API Key 也已配好。

3

运行 SEAM 的迁移指令

下载 SEAM、安装依赖，并在 SEAM 项目根目录运行 bash src/scripts/run_seam.sh <你的项目路径>。

4

等待 SEAM 自动处理

SEAM 命令行运行时，日志默认是简化输出的 TUI，也可以按 q 退出 TUI 直接以 log 输出运行。根据 SEAM 的百模适配经验，绝大部分项目在 30 分钟内能完成迁移，最长的也有几个小时。如果超过 30 分钟，建议查阅日志看迁移 phase 进度，以及看是否迁移异常。

5

查看迁移结果并使用迁移后项目

迁移结束后终端会显示是否通过端到端验证，常见成功标识包括 E2E TEST PASSED / E2E PASS。迁移后的文件夹位于 --output-dir 指定目录；未指定时默认写入 SEAM 仓库同级目录 ../output_projects/<项目名>_<时间戳>/。根据 migration_reports/USAGE.md 中 ## Run 章节建议的运行指令来使用。

FAQ

常见问题

关于迁移原理、支持范围、结果解读与联系方式的常见疑问。

SEAM 是一款基于 YAML 配置的轻量化模型适配迁移工具，核心作用是帮助开发者自动化、一键完成大模型跨硬件 GPU 迁移适配，解决代码或模型从英伟达生态迁移至中国国产异构 GPU 算力硬件时，代码报错、算子不兼容、推理运行异常等适配难题。SEAM 具备「自进化越用越聪明」「幻觉控制确保迁移结果真实有效」两大核心优势。

模型适配迁移，指将原本适配 CUDA 架构的大模型推理/训练代码、运行环境、调用逻辑，适配至国产异构 GPU 硬件可运行、并且性能调优发挥好硬件本身能力。

目前 SEAM 已完成适配的硬件与框架：

  • GPUs：阿里平头哥 PPU、华为昇腾 Ascend、沐曦 MetaX 国产异构 GPU
  • 框架：PyTorch 原生框架、vLLM 高速推理框架、SGLang 大语言模型服务框架

如需交流或反馈，请通过 SEAM 开源仓库的 Issues 联系项目团队。

硬件层面的 CUDA 兼容属于指令集 / 基础 API 浅层兼容，并非 100% 全量 CUDA 算子、底层内核、高阶接口完美兼容，甚至每一版本的硬件发布实际都需要对应的调整兼容以发挥好硬件本身能力。

因此需要 SEAM 完成算子替换、底层调度逻辑改写、性能调优等，兼顾可用性 + 运行性能。

SEAM 迁移任务执行完后：

  • 会直接在终端显示是否跑通：E2E TEST PASSED / E2E PASS 或失败信息；也可以通过 ./e2e-reports/migration_utils/<时间戳>/summary.json 获取更具体的信息。
  • 迁移的代码库：会默认写入 ./output_projects/<项目名>_<时间戳>/，或是执行时输入的参数 --output-dir。使用迁移后的代码库，即可在国产 GPU 上运行。
  • 迁移报告：会在迁移后的代码库下创建 migration_reports/ 文件夹，用于查看迁移后项目本身的验收结果、性能、custom-op 迁移情况、构建日志等。
细节运行时 log 存在迁移后项目的 .sm-artifacts/ 下；如果运行失败，可以把运行报告和 .sm-artifacts/ 一起反馈给我们排查。 运行时 .memory 和 .skill 等文件夹会更新，是 SEAM 自进化学习的经验记忆和技能素材，非必要勿删。
